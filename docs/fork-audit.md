## Assertion and upstream-safety review

- Original-to-current test comparison finds no missing fork recovery/retained-prefix
  test titles. Counts are a navigation aid, not a proof: assertion bodies and altered
  call contracts were inspected. Browser changes above strengthen the relevant
  attachment boundary instead of weakening it to unrelated global read counts.
- The removed `offsetActivityPhaseBoundary` helper/test is replaced by the one-time
  merge offset in `mergeEditedMessageContent`; its boundary assertions remain in
  `packages/data-provider/specs/messages.spec.ts` and step-handler coverage. This is
  a moved responsibility, not removal of phase-index semantics.
- Partial-disconnect tests now reject another epoch outright (not persist it without
  metadata), and parameterize ordinary/retained/prefix-only snapshots; OAuth filtering
  and provenance assertions remain. HITL projects retained content for persisted/final
  messages, keeps approval provenance completion-local in the job store, and retains
  upstream's separate model-bound private-text admission preflight.
- Upstream changes to early tool completion buffering, compaction anchors, temporary
  retention, two-factor enrollment redirects, query-cache fixtures, Jotai queue ownership,
  menus and dialog themes remain intact. Former warning-only tests now assert buffered
  tool output; these are upstream behavior changes, not dropped fork features.
- Existing backend/shared-client typechecks and affected static gates passed (see R).
  This audit changes environment/docs only; no application behavior was patched.
